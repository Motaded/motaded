# Market Indicators — шар даних для головної сторінки

Документ описує архітектуру, контракт даних, mapping World Bank, схему БД і пайплайн для таблиці та графіка «Market / Economic Indicators». Призначений для імплементації в Drupal (без прив’язки до конкретних комітів коду).

---

## Продуктова конфігурація v1 (затверджено)

| Область | Рішення |
|---------|---------|
| **KPI-смуга** | Ручні поля в **Paragraph** або **блоці** (~5 значень). Окремо від API-таблиці; не змішувати джерела даних. |
| **Таблиця (API)** | Рівно **6 рядків** (див. §5.1 v1). Без exports / imports / туризму на старті. |
| **Графік (API)** | Одна серія: **GDP Growth** (`gdp_growth`). Роки: **динамічні останні 6 років** — від `(поточний_рік - 5)` до `поточний_рік` включно (не хардкодити 2018–2023). |
| **Валюта** | **Лише USD**, як у World Bank: **без** конвертації в SAR, **без** курсів. Приклад підпису в UI для FDI: `US$ 96B` (точний формат — у форматтері). |
| **Мова UI v1** | **EN only** для labels таблиці/графіка. Пізніше: `t()` або config translation. |
| **Розклад** | Імпорт **1× на день** (cron + queue). Якщо API впав — показуємо **останній успішний** snapshot у БД. |
| **IMF** | **Не використовується в v1** (складніший API; не потрібен для MVP). |
| **Дизайн** | Мінімальний gov-стиль: **без** тіней, **без** «карток» навколо таблиці; таблиця = семантична `<table>`; графік = проста **line**. Data-first, джерела завжди видно. |

**Логіка набору v1:** core-макро, мінімум шуму, переважно прямий mapping на WDI для `SAU`.

---

## 1. Мета та межі системи

**Мета:** надійні, нормалізовані макро-показники (GDP growth, population, FDI тощо), які допомагають зрозуміти бізнес-середовище Саудівської Аравії. Це **керована дата-система**, а не редакційний контент.

**Не входить у цей шар:**

- KPI-смуга зверху (великі цифри на кшталт +8.7%, 36M+) — **лише вручну** через **Paragraph або block fields** (~5 значень), з мотивів стабільності, юридичної передбачуваності та форматування; **не змішувати** з рядками API-таблиці.
- Вузли Drupal / content types для зберігання імпортованих рядків індикаторів — **не використовувати** для цього шару.

---

## 2. Архітектура (end-to-end)

```text
Зовнішні API (v1: лише World Bank)
       ↓
Cron (1×/день) → Queue (не блокувати весь cron)
       ↓
HTTP-клієнт (таймаут, ретраї)
       ↓
Нормалізація + форматування (одиниці, округлення, підписи)
       ↓
Локальне сховище: таблиці БД (+ опційно JSON snapshot для швидкого читання)
       ↓
Preprocess → Twig / drupalSettings (лише локальні дані)
       ↓
Таблиця + графік (без викликів API з браузера)
```

**Принципи:**

- Стабільність: при падінні API залишається **останній успішний snapshot**.
- Продуктивність: рендер читає **локальні** структури.
- Єдине місце контролю формату: **один сервіс нормалізації** на бекенді.

## 3. Джерела даних

| Пріоритет | Джерело | Примітки |
|-----------|---------|----------|

## 4. Внутрішній контракт даних (рядок індикатора)

Поле | Тип / призначення
-----|-------------------
`indicator_key` | Machine name, стабільний ключ (напр. `gdp_growth`).
`label` | Текст для UI. **v1:** EN-рядки в коді/config без обов’язкового `t()`. **Пізніше:** `t()` / config translation.
`value_raw` | Число для логіки та графіків (float / numeric).
`value_display` | Відформатований рядок для таблиці (`+8.7%`, `36.2M`, тощо).
`year` | Рік останнього спостереження (int), якщо річні дані.
`period` | Опційно: `year` / квартал (`2023-Q1`) — для річних vs квартальних серій.
`period_type` | Рекомендовано явно: `annual` \| `quarterly` (у БД — окрема колонка або угода в `period`).
`source_name` | Обов’язково (напр. `World Bank`).
`source_url` | URL на джерело / портал даних.
`fetched_at` | Час останнього успішного імпорту (аудит).
`provider` | `worldbank` \| `manual` (v1); пізніше можна додати `imf`.

**Часові ряди для графіка:** масив об’єктів `{ "year": int, "value_numeric": float }` (або еквівалент у БД — див. §6). Можна дублювати `source_name` на рівні серії або тримати метадані серії окремо.

## 5. Mapping World Bank → `indicator_key` (країна `SAU`)

### 5.1 Таблиця на головній — рівно 6 рядків (v1)

| # | `indicator_key` | Label (EN v1) | World Bank code | Примітки |
|---|-----------------|---------------|-----------------|----------|
| 1 | `gdp_growth` | GDP Growth | `NY.GDP.MKTP.KD.ZG` | Реальний зростання ВВП, **%**; та сама серія для **графіка**. |
| 2 | `population` | Population | `SP.POP.TOTL` | Кількість осіб; формат на кшталт `36.2M` у `value_display`. |
| 3 | `fdi_inflow` | FDI Inflows | `BX.KLT.DINV.CD.WD` | **Current US$** у WDI; у UI v1 підкреслювати **US$** (напр. `US$ 96B`), без SAR. |
| 4 | `non_oil_gdp_growth` | Non-oil GDP Growth | *див. нижче* | Окремий національний показник «non-oil» **часто відсутній** як один стандартний WDI-код для KSA. **v1:** або (а) підтвердити один WDI-проксі під час імплементації, або (б) тримати рядок із **`provider: manual`** + значення з **config fallback**, з прозорим `source_name` / `source_url` (напр. GASTAT, якщо команда юридично схвалить текст). |
| 5 | `inflation` | Inflation Rate | `FP.CPI.TOTL.ZG` | **%**. |
| 6 | `unemployment` | Unemployment Rate | `SL.UEM.TOTL.ZS` | **%**. |

**Не входить у v1:** exports, imports, tourism (додати пізніше за тим самим патерном).

### 5.2 Графік (v1)

- **Ключ серії:** лише `gdp_growth`.
- **Діапазон років:** для кожного імпорту та рендеру обчислювати `year_min = current_calendar_year - 5`, `year_max = current_calendar_year`; у БД `market_indicator_series` зберігати/оновлювати точки в цьому діапазоні (або ширше з API, але на графік віддавати лише ці 6 років). Це гарантує «живий» вигляд без хардкоду.

### 5.3 Приклад запиту API

```http
GET https://api.worldbank.org/v2/country/SAU/indicator/NY.GDP.MKTP.KD.ZG?format=json&per_page=10
```

Відповідь: масив точок з роком і `value` (число або `null`). Нормалізація: округлення + побудова `value_display` (напр. `+8.7%` для темпів зростання).

### 5.4 Backlog mapping (не v1)

Після релізу v1 можна додати, зокрема: `exports` (`NE.EXP.GNFS.CD`), `imports` (`NE.IMP.GNFS.CD`), `tourism` (`ST.INT.ARVL`), `gdp_total`, `gdp_per_capita`, `internet_users` — за потреби продукту.

### 5.5 Приклад нормалізованого рядка (після обробки)

```json
{
  "indicator_key": "gdp_growth",
  "label": "GDP Growth",
  "value_raw": 8.7,
  "value_display": "+8.7%",
  "year": 2023,
  "period_type": "annual",
  "source_name": "World Bank",
  "source_url": "https://data.worldbank.org",
  "provider": "worldbank",
  "fetched_at": "2026-05-11T12:00:00Z"
}
```

**Важливо:** World Bank повертає значення на кшталт `8.734928374` — у БД можна зберігати більшу точність у `value_raw`, а для UI формувати `value_display` централізовано.

## 6. Схема бази даних (production-oriented)

Розділення: **останні / табличні значення** vs **часові ряди для графіків**.

### 6.1 Таблиця `market_indicators`

Призначення: рядки для таблиці на головній, «останнє» значення на рік per ключ.

| Колонка | Тип | Примітки |
|---------|-----|----------|
| `id` | serial / auto-increment | PK. |
| `indicator_key` | varchar(64) | NOT NULL. |
| `label` | varchar(255) | NOT NULL; для перекладів можна пізніше винести в config + `t()`. |
| `value_raw` | numeric | NULL якщо немає даних. |
| `value_display` | varchar(64) | NULL дозволено. |
| `year` | int | NULL якщо невизначено. |
| `period` | varchar(16) | Опційно: `year` або квартал. |
| `period_type` | varchar(16) | Рекомендовано: `annual` \| `quarterly`. |
| `source_name` | varchar(255) | |
| `source_url` | text | |
| `provider` | varchar(64) | `worldbank` \| `manual` (v1); за потреби пізніше `imf`. |
| `fetched_at` | timestamp | |

**Обмеження:** `UNIQUE(indicator_key, year)` — при оновленні того ж року виконувати UPSERT.

> **Drupal:** оголосити через `hook_schema()` у кастомному модулі; для MySQL використовувати `serial`/`int` + `auto_increment` за стандартом API схеми Drupal, не обов’язково літеральний `SERIAL` PostgreSQL.

### 6.2 Таблиця `market_indicator_series`

Призначення: точки лінії для графіка (v1: **GDP Growth**, останні 6 років — див. §5.2).

| Колонка | Тип | Примітки |
|---------|-----|----------|
| `id` | serial / auto-increment | PK. |
| `indicator_key` | varchar(64) | NOT NULL; зазвичай одна серія на ключ (напр. лише `gdp_growth`). |
| `year` | int | NOT NULL. |
| `value` | numeric | Число для осі Y. |
| `source_name` | varchar(255) | Опційно на точку; або джерело на рівні метаданих серії в коді. |

**Обмеження:** `UNIQUE(indicator_key, year)`.

### 6.3 Опційний JSON snapshot

Для мінімізації запитів до БД на кожен хіт: зберігати агрегований JSON останнього успішного імпорту (наприклад у `keyvalue` або окремій колонці / таблиці `market_indicators_snapshot`) з версією схеми `schema_version`, щоб preprocess міг читати один блоб. Джерелом істини залишаються таблиці §6.1–6.2; snapshot — похідний кеш.

## 7. Пайплайн імпорту

1. **Cron 1× на день** — постановка задач у чергу або короткий kick-off (не блокувати довгим HTTP).
2. **Queue workers** — фактичні HTTP-запити та парсинг, щоб не перевищувати ліміт часу cron.
3. **HTTP:** таймаут, обмежена кількість ретраїв з backoff, логування помилок (`logger`).
4. **Нормалізація (v1):** **USD** для грошових величин як у WB; **без SAR і без FX**; округлення та `value_display` (у т.ч. `%`, `US$ …B`); річні дані — `period_type: annual`.
5. **Запис:** транзакція або послідовний UPSERT у `market_indicators` та `market_indicator_series` (серія `gdp_growth` за діапазоном §5.2).
6. **Помилка API:** **не** видаляти останній успішний snapshot; UI продовжує показувати старі дані до наступного успішного імпорту.

**Ручний fallback:** для `indicator_key` з `provider = manual` значення з config/state зливаються після або до API-шару за чітким пріоритетом (документувати в коді: наприклад manual перекриває лише відсутні ключі).

## 8. Шар рендеру (Drupal)

- **Twig:** лише змінні з preprocess; цикл по `indicators` для `<tr>`.
- **Графік:** дані тільки з `drupalSettings.marketIndicators.series` (або inline JSON з сервера), без `fetch` до World Bank/IMF з клієнта.
- **Стиль UI (v1):** мінімальний gov: без тіней, без карток-обгорток; таблиця = чиста `<table>`; графік = проста лінія; джерела завжди видимі; без dashboard-шуму.

Приклад Twig (концептуально):

```twig
{% for row in indicators %}
  <tr>
    <td>{{ row.label }}</td>
    <td>{{ row.value_display }}</td>
    <td>{{ row.year }}</td>
    <td>{{ row.source_name }}</td>
  </tr>
{% endfor %}
```

Приклад передачі серії в JS (концептуально):

```js
const series = drupalSettings.marketIndicators.gdp_growth;
// series = [{ year: Y-5, value: … }, …, { year: Y, value: … }]  // 6 років, див. §5.2
```

## 9. Граничні випадки

| Ситуація | Поведінка |
|----------|-----------|
| Різні роки для різних рядків | У таблиці завжди показувати **фактичний `year` per row**. |
| Валюта (v1) | Лише **US$** у форматованому виводі для грошових індикаторів; SAR не використовувати. |
| Річні vs квартальні | v1 — річні (`annual`); квартали — пізніше, якщо з’явиться вимога. |
| Мова (v1) | Labels EN; переклади — post-v1. |
| Відсутнє значення в API | Не стирати попередній успішний рядок; опційно приховати рядок у UI, якщо NULL і так вирішить продукт. |
| Non-oil рядок | Доки немає стабільного WB-рядка — manual config + чесне джерело в колонці Source. |
